# Working on `l`

`l` is a human-readable, extensible language. L, Lyger and Logiceme are Go implementations. Lyger resolves source semantics and emits AML; Logiceme generates Rust from AML and canonical builtin/logeme resources. An `Executable` is a source bundle; the CLI builds and publishes it. App process supervision is the execution boundary. Other L constructs compile to Rust operations; do not implement a second L interpreter or Function dispatch runtime.

Read [architecture](docs/architecture.md), [CLI/runtime semantics](docs/cli-build.md) and [development/acceptance](docs/development-harness.md). Read scoped instructions before changing these areas:

- [cmd/l/AGENTS.md](cmd/l/AGENTS.md): CLI, publication and tested compiler state.
- [lyger/AGENTS.md](lyger/AGENTS.md): frontend, grammar and bindings.
- [logiceme/AGENTS.md](logiceme/AGENTS.md): backend and native resource integration.

Lyger owns grammar, bindings, types, paragraph activation, definite assignment and capture/ownership analysis. Logiceme owns callable declarations, glyph punctuation and support assembly. Lyger may encode resolved native type/name/value atoms in approved AML fields; those atoms contain no executable Function body or closure. Functions must instantiate their selected builtin/logeme definitions for construction, invocation and returns. Each Function declaration also binds its invocation verb; do not add a `Call` primitive. Recognizing a Function marker and then emitting Rust independently violates this boundary. Do not hide generated bodies, closures or dispatch implementations in `Statement`, EA or native-string leaves; resolved native type/lifetime atoms remain typed AML bindings. Native leaves perform one call, operator, constructor, borrow/projection or bounded pattern/binding. Branches, loops, error policy, resource selection and sequencing belong in L word definitions; Print is a composition. Do not hide these algorithms in native helpers or closures.

Use the approved [Lifetimes and GenericTypes inputs](builtins/README.md#lifetime-and-generic-inputs) through AML: local String interiors on FW/HY/MY/Y/named KY, never Func/Prop/Op fields or inherited defaults. Compose existing syllables and builtin definitions without changing frozen interfaces. Native helpers may implement resolved storage and ownership, but cannot replace typed Functions with erased argument/result vectors and runtime L-signature dispatch. Preserve opaque authored native leaves, source assignment and explicit capture transfers; invent no initialization or blanket cloning.

Rust excludes Deferred from its logeme templates and rejects supplied Deferred metadata. Preserve this [target contract](builtins/README.md#execution-without-deferred); do not introduce deferred-call semantics or infer runtime cleanup from scheduling.

Apps execute in separate OS processes owned by the orchestrator. Run launches; Stop requests termination without joining; Await joins finalized output and activates its continuation once. Output is raw stdout, including whitespace and newlines. Builtin logeme implementations use compiler-typed process bindings. Start/Execute retain their `any App` source signatures. Pronouns bind the last subject defined in their source paragraph; possessives perform member access. Native macOS/Linux execution is supported; Phase 2 in-code concurrency and cross-compilation are outside scope.

Standalone Service declarations remain structural: they produce no package or process, and standalone Service bodies and native lifecycle/runtime-member use reject. Only Apps own process lifecycle and continuations. Preserve Main/Basic construction, primary Service topology, raw AML library/bin targets, and version-1 App publication. Objects remain files and Classes remain module/source groups, not runtime scopes.
